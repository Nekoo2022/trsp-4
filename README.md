# TRSP-4

Здесь лежит небольшой FastAPI-проект: миграции Alembic, работа с SQLite, обработка ошибок, валидация через Pydantic и тесты на pytest. Ниже — как я сам обычно поднимаю всё с нуля и что имеет смысл потыкать руками.

## Как запустить у себя

Нужен **Python 3.10+**. Дальше из корня репозитория:

```bash
python3 -m venv .venv
source .venv/bin/activate          # на Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Если хочешь проверить куски, где фигурирует таблица `products`, подними базу через Alembic. Я делаю так: сначала первая ревизия, потом заливаю пару строк из скрипта (это по сути шаг из задания с «ручной» вставкой), потом докатываю до конца:

```bash
alembic upgrade 20250401_1
sqlite3 app.db < seed_after_migration_1.sql
alembic upgrade head
```

Сервер:

```bash
uvicorn app.main:app --reload
```

Интерактивная дока у FastAPI из коробки — открой в браузере [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs), там удобно дергать ручки без Postman.

## Что имеет смысл проверить глазами

**Жив ли сервер** — зайди на `GET /health`, должен вернуться что-то вроде `{"status":"ok"}`.

**Валидация тела запроса (задание 10.2)** — ручка `POST /users`. В `/docs` видно схему: попробуй нормальный JSON и заведомо кривой (не тот email, возраст не больше 18, короткий пароль). На ошибках жду **422** и свой формат с `error_code` и списком `issues` — не дефолтный «голый» ответ FastAPI.

**Свои исключения (10.1)** — `GET /check-condition` без `ok=true` должен отдать **400**, а `GET /items/1000` — **404**, оба с понятным телом ответа.

**Реестр в памяти (11.1)** — префикс `/registry/accounts`: создал пользователя POST-ом, прочитал GET-ом по id, удалил DELETE-ом. Всё хранится в словаре в процессе, после перезапуска сервера данные, конечно, пропадут.

**Проверка схемы после миграций** — `GET /products/schema-check` имеет смысл вызывать только если ты реально прогнал миграции и таблица `products` есть. Иначе будет не то, что ожидаешь.

Про **11.2**: там отдельное маленькое приложение в `app/task_11_2_app.py` с теми же тремя методами `/users`, что в методичке. Я его **не вешал** на основной `app.main`, чтобы не пересечься с `POST /users` из 10.2. Поэтому «пощупать в браузере» его не выйдет — зато оно полностью покрыто асинхронными тестами (см. ниже).

## Тесты

Разом прогнать всё:

```bash
pytest tests/ -v
```

Если хочешь по файлам (так я быстрее локализую, где что сломалось):

```bash
pytest tests/test_user_validation.py -v       # 10.2, валидация
pytest tests/test_assignment_11.py -v         # 11.1, /registry
pytest tests/test_assignment_11_2_async.py -v # 11.2, async + Faker
```

Меньше болтологии в консоли:

```bash
pytest tests/ -q
```
